# Dinggo cars and repair quotes

CakePHP application that imports cars and repair quotes from the Dinggo API into MySQL and displays them locally. PHP, Nginx and MySQL run through Docker Compose.

## Setup

Requires Docker Desktop (running) or Docker Engine with Compose v2, plus a POSIX shell and OpenSSL. Host PHP, Composer and MySQL are not required.

```sh
./scripts/setup.sh
```

This creates `.env` if missing, generates local secrets and host UID/GID values, builds PHP, installs dependencies from `app/composer.lock`, prepares writable directories and starts services. It preserves an existing `.env` and database volume. It does **not** run migrations or imports.

Add your API credentials to the root `.env` using placeholders below as a guide:

```dotenv
DINGGO_API_BASE_URL=https://app.dev.aws.dinggo.com.au/phptest
DINGGO_USERNAME=<your-api-username>
DINGGO_KEY=<your-api-key>
```

Then apply configuration and create the database tables:

```sh
docker compose up -d --wait
docker compose exec app php bin/cake.php migrations migrate
docker compose exec app php bin/cake.php migrations status
```

The migrations in `app/config/Migrations/` create `cars` and `quotes`, with quotes linked to cars by a foreign key.

## Environment variables

`.env.example` documents the settings; real credentials belong only in the Git-ignored `.env`.

| Variable | Purpose / default |
| --- | --- |
| `APP_PORT` | Local HTTP port; `8080` |
| `LOCAL_UID`, `LOCAL_GID` | PHP container user/group; setup uses your host IDs |
| `CAKE_DEBUG` | CakePHP debug mode; `true` for local development |
| `SECURITY_SALT` | Random application secret generated by setup |
| `MYSQL_DATABASE`, `MYSQL_USER` | Database and application user; both default to `cakephp` |
| `MYSQL_PASSWORD`, `MYSQL_ROOT_PASSWORD` | Separate random passwords generated by setup |
| `DINGGO_API_BASE_URL` | API base URL shown above |
| `DINGGO_USERNAME`, `DINGGO_KEY` | Supplied API credentials, required for imports |

Compose passes database settings to the app as `DB_*` variables with hostname `db` and port `3306`. Run `docker compose up -d` after changing `.env`. MySQL initialization settings only apply to an empty volume; changing passwords in `.env` does not update existing database users.

## Import and usage

Run cars first, then quotes:

```sh
docker compose exec app php bin/cake.php import_cars
docker compose exec app php bin/cake.php import_quotes
```

- `import_cars` adds cars or updates matches by license plate **and** state. A failed import rolls back all car changes in that run.
- `import_quotes` fetches quotes for every saved car and replaces that car's existing quotes in a transaction. An empty result clears its quotes. On failure, that car's previous quotes are kept and processing continues; the command exits with an error if any car fails.

Open **http://localhost:8080/** (or your `APP_PORT`). `/` and `/cars` list saved cars, ordered by plate and state. Select **View quotes** to open `/cars/view/{id}` and see the car details, repairer, price and overview of work. Import commands populate the data; browsing reads the saved records.

## Development commands

```sh
docker compose up -d --wait          # Start
docker compose stop                 # Stop; retain data
docker compose down                 # Remove containers/network; retain data
docker compose up -d --build --wait # Rebuild
docker compose exec app composer install
docker compose exec app php bin/cake.php --help
docker compose exec app vendor/bin/phpunit
docker compose exec app php config/verify-database.php
docker compose logs --tail=100 app nginx db
```

Tests use SQLite at `app/tmp/tests.sqlite`; the test bootstrap applies migrations to the test database.

## Files, data and troubleshooting

- `app/` is bind-mounted for local editing; `app/config/docker.php` reads environment configuration.
- `docker/php/` and `docker/nginx/` contain runtime configuration. Nginx serves `app/webroot/` on localhost only.
- `app/tmp/` and `app/logs/` hold writable runtime files and are ignored by Git.
- MySQL data persists in the Compose project's `mysql_data` named volume. MySQL is not exposed on a host port; PHP startup waits for its health check.
- **Port conflict:** change `APP_PORT` in `.env` and recreate services with `docker compose up -d`.
- **Permission errors:** match `LOCAL_UID`/`LOCAL_GID` to `id -u`/`id -g`, then run `chmod -R u+rwX,go-w app/tmp app/logs` and recreate services. If these directories are owned by root, repair their ownership first.
- **Database/API errors:** inspect logs and command output; check database credentials against the existing volume and supply valid Dinggo credentials before importing.

**DESTRUCTIVE: delete all local database data**, then recreate the tables (imports must be rerun):

```sh
docker compose down --volumes
docker compose up -d --wait
docker compose exec app php bin/cake.php migrations migrate
```
